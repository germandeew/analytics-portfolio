# Сквозная аналитика по проданным лидам

**2026, IT-агентство · роль: отвечал за архитектуру и реализацию BI-системы с нуля**

## Ситуация

Когда я пришёл в компанию в январе 2026 года, отделу продаж нужно было понять,
окупаются ли наши лиды клиентам. После передачи лида его дальнейший путь и результат
были видны только в CRM клиента. Задача состояла в том, чтобы заранее замечать
проблемы с экономикой клиента: видеть сделки, выручку и маржу по нашим лидам,
сравнивать результат со средним по сегменту и городу.

## Что сделал

- Выбрал стек и спроектировал систему: PostgreSQL для хранения данных и расчётов,
  Airflow для загрузки, Docker для запуска сервисов, Apache Superset для отчётов.
- Разработал интерфейс подключения клиентов. Он получал сведения из CRM компании,
  определял доступные интеграции с amoCRM и Битрикс24 и позволял подключать
  клиентов к аналитике. Для клиентов без вебхука нашёл другой способ получать статусы.
- Создал общую воронку для разных клиентских CRM. Система предварительно
  сопоставляла статусы по словарю близких формулировок, а менеджер по продажам,
  ведущий клиента, проверял соответствия и при необходимости исправлял их.
- Сначала связывал переданные лиды со сделками в CRM клиента по номеру телефона
  и дате передачи. Затем перешёл на ID, который CRM возвращала при получении лида.
- Вместо двух загрузок в день настроил регулярное получение только изменившихся
  данных, чтобы не забирать одни и те же записи повторно.
- Настроил расчёты CPL, CPA, выручки и маржи по доступным данным. Там, где данных
  хватало, сравнивал маржу клиента со средней по сегменту и городу и выводил
  показатели в дашбордах Apache Superset.

## Результат

С июня 2026 года систему использовали в работе. К ней подключили около 320 клиентов
из разных сфер, включая автобизнес, стоматологии и недвижимость. Одновременно
работали 18–20 дашбордов по сегментам, в каждом было примерно 16–20 показателей.
Отдел продаж видел результат по переданным лидам и экономику сотрудничества;
по отчётам принимались решения о работе с конкретными клиентами.

Не все клиенты корректно заполняли выручку в своей CRM. По таким клиентам
достоверно посчитать маржу по нашим лидам было нельзя.

## Стек

PostgreSQL, SQL, Airflow, Docker, Apache Superset, API amoCRM и Битрикс24.
