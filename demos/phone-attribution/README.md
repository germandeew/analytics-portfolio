# Атрибуция по телефону и проверки перед выпуском отчёта

Задача из маркетинговой аналитики: у продукта несколько каналов привлечения. Наши каналы (SMS,
звонки и мессенджеры) касаются людей по номеру телефона, а регистрации и оплаты приходят с сайта.
Нужно честно посчитать, какой канал привёл регистрацию и деньги, и не выпустить отчёт, если
данные сломаны.

Данные выдуманные, код написан с нуля для портфолио. Только стандартная библиотека Python 3.9+
и встроенный SQLite.

## Правило атрибуции

Правило записано в одном месте (`ATTRIBUTION_SQL` в `attribute.py`):

1. Метка рекламы или партнёра у регистрации главнее всего: это чужой канал, наше касание его не перебивает.
2. Иначе выигрывает последнее касание наших каналов по тому же телефону за 10 дней до регистрации.
3. Иначе это органика.

Оплата наследует канал своей регистрации. Телефоны приводятся к виду `79XXXXXXXXX`:
`+7 (912) 345-67-89`, `8 912 345 67 89` и `9123456789` — один и тот же человек.

## Проверки перед выпуском

Отчёт выходит со статусом **OK** или **HOLD**. Код выхода 2 при HOLD, чтобы планировщик не
опубликовал битые цифры.

| Проверка | Что ловит |
|---|---|
| Мусорные телефоны ≤ 3 % | сломанную выгрузку или смену формата номера |
| Оплаты без регистрации = 0 | потерю регистраций или чужие оплаты в выгрузке |
| Сверка выручки с оплатами | ошибки соединений: размножение или потерю строк |
| Источник не молчит | день без регистраций, когда до этого их было много, а касания идут |

Последняя проверка появилась из практики. Источник регистраций может замолчать, и тогда отчёт
тихо показывает падение канала, хотя упал не канал, а выгрузка. Такие ошибки не падают с
исключением, а молча меняют числа, поэтому у каждого правила должен быть свой сторож.

## Запуск

```bash
python3 generate.py                     # выдуманные данные в data/
python3 attribute.py                    # отчёт в report.md, код выхода 0 или 2
python3 generate.py --silent-day        # последний день без регистраций
python3 attribute.py                    # → выпуск: HOLD, код выхода 2
python3 -m unittest -v                  # 10 тестов: формат телефонов, окно, приоритеты, проверки
```

## Пример отчёта

```text
# Атрибуция регистраций и оплат — выпуск: OK

| Канал | Группа | Регистраций | Доля | Платящих | Выручка, ₽ | ₽ на регистрацию |
|---|---|---:|---:|---:|---:|---:|
| messenger | наши | 75 | 7.6% | 21 | 53 700 | 716 |
| sms | наши | 68 | 6.9% | 16 | 39 000 | 574 |
| call | наши | 76 | 7.7% | 12 | 24 000 | 316 |
| organic | другие | 476 | 48.4% | 105 | 229 800 | 483 |
| ads | другие | 152 | 15.5% | 36 | 74 700 | 491 |
| partner | другие | 136 | 13.8% | 29 | 66 600 | 490 |

## Проверки

- OK   Мусорные телефоны: 0.8% при пороге 3%
- OK   Оплаты без регистрации: 0
- OK   Сверка выручки с оплатами: расхождение 0.00 ₽
- OK   Источник регистраций не молчит: пропусков нет
```

С `--silent-day` последняя строка становится такой:
`HOLD Источник регистраций не молчит: 2026-09-30: 0 при среднем 35.1`.

## Как читать такие цифры

Долю регистраций и долю выручки стоит показывать вместе: канал с небольшой долей регистраций может
приносить заметно больше денег на регистрацию. Окно в 10 дней и приоритет меток — решение бизнеса,
а не код. Их стоит согласовать с владельцем продукта и записать, а при смене правила пересчитать
историю, а не только новые дни.
